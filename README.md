# VJ Portfolio (Dani)

Next.js портфолио сайт за VJ визуализации, с админ панел за редакция на текстове, снимки и видеа — без нужда от код.

## Технологии

- **Next.js 16** (App Router) + TypeScript + Tailwind CSS 4
- **Prisma** + PostgreSQL — база данни за съдържанието
- **NextAuth (Auth.js) v5** — защита на админ панела
- **Cloudflare R2** (S3-съвместим storage) — за видеата и снимките
- Шрифтове: **Tektur** (заглавия) + **JetBrains Mono** (текст, поддържа кирилица)

## Как работи "без база данни"

Сайтът е направен така, че **винаги изглежда завършен**, дори преди да свържете база данни:
всяко извикване към базата (в `src/lib/data.ts`) automatически пада обратно към вградено
съдържание в `src/lib/content.ts`, ако базата липсва, не отговаря или е празна. Затова можете
да пуснете сайта локално или да го качите на Vercel веднага, без предварителна настройка — а
после да добавите база данни, за да можете да редактирате нещата от админ панела.

## Локално стартиране

```bash
npm install
cp .env.example .env   # вече е направено - презапишете стойностите както искате
npm run dev
```

Отворете http://localhost:3000 — сайтът ще работи веднага с вграденото демо съдържание
(стокови снимки placeholder-и, примерни текстове).

## Админ панел

Достъпен е на **`/admin900`** (не е линкнат никъде в сайта и е скрит за търсачки чрез
`robots.txt`). Оттам може да редактирате:

- Текстовете на цялата начална страница (hero, контакти, SEO)
- Всеки проект — заглавие, описание, дати, цветове, "секциите" със символика (напр. Андреа /
  Биляниш / Джия), както и медията (видео + 3 снимки за началната страница + галерия за
  страницата "See more")
- Социалните мрежи (линкове + икони)
- Съобщенията от контактната форма

### Данни за вход

Генерирани са автоматично при първоначалната настройка:

- **URL:** `/admin900`
- **Потребител:** `admin`
- **Парола:** виж стойността, която ти беше показана в чат-а (пази я на сигурно място)

За да смените паролата по-късно:

```bash
npm run hash-password -- "новата-парола"
```

Командата ще изпише готов ред за `.env` (с вече ескейпнати `$` знаци — важно е да ги оставите
точно така, иначе Next.js "изяжда" хеша, защото го бърка с променлива), както и суров хеш за
поставяне в Vercel's environment variables (там не се налага escaping).

## Свързване на база данни (нужно, за да могат промените от админ панела да се запазват)

Препоръчано - безплатен **[Neon](https://neon.tech)** Postgres (перфектно съчетание с Vercel):

1. Направете си акаунт в neon.tech и създайте нова база.
2. Копирайте connection string-а (нещо от рода `postgresql://user:pass@host/db?sslmode=require`).
3. Поставете го като `DATABASE_URL` в `.env` (локално) и в Vercel → Project → Settings →
   Environment Variables (за продукция).
4. Приложете схемата към базата:

   ```bash
   npm run db:push
   ```

5. Пуснете `npm run dev` (или деплойнете) и отидете на `/admin900` → на таблото ще видите
   бутон **"Зареди начално съдържание"** — той копира демо съдържанието (проекти, текстове,
   placeholder снимки) в базата, за да имате от какво да редактирате, вместо да пишете всичко
   от нула. Алтернативно, локално можете да пуснете `npm run db:seed`.

## Качване на видеа/снимки (Cloudflare R2)

Докато нямате R2 достъп, просто поставяйте линкове към снимки/видеа в текстовите полета в
админ панела — работи с всеки публично достъпен URL. Когато сте готови с R2:

1. Създайте R2 bucket в Cloudflare dashboard-а и си направете API токен (Access Key
   ID/Secret) с права за writing в bucket-a.
2. Направете bucket-а публично достъпен (Public Access / custom domain) — това ще е вашият
   `R2_PUBLIC_URL`.
3. Попълнете в `.env` / Vercel:

   ```
   R2_ACCOUNT_ID=...
   R2_ACCESS_KEY_ID=...
   R2_SECRET_ACCESS_KEY=...
   R2_BUCKET_NAME=...
   R2_PUBLIC_URL=https://media.вашия-домейн.com
   ```

4. От този момент бутонът **"Качи"** до всяко поле за видео/снимка в админ панела ще качва
   директно към R2 и ще попълва линка автоматично.

## Контактна форма

Съобщенията от формата винаги се записват в базата данни (виждате ги в `/admin900/messages`).
По желание, за да получавате и имейл известие при ново съобщение, добавете:

```
RESEND_API_KEY=...              # безплатен акаунт на resend.com
CONTACT_NOTIFICATION_EMAIL=your@email.com
```

## Деплой във Vercel

1. Качете проекта в GitHub (или друг git host).
2. Импортирайте repo-то във Vercel.
3. Добавете всички environment променливи от `.env.example` в Vercel → Settings →
   Environment Variables (виж инструкциите по-горе за DATABASE_URL, ADMIN_PASSWORD_HASH,
   AUTH_SECRET, R2_*, NEXT_PUBLIC_SITE_URL).
4. Деплойнете. При първи build Prisma Client се генерира автоматично (`postinstall`
   скрипт).
5. След деплой, отворете `/admin900` на живия домейн и заредете началното съдържание (виж
   стъпка 5 по-горе), после подменете снимки/видеа/текстове с истинските.

## SEO

- Динамични `<title>`/`<meta description>`/Open Graph тагове от настройките в админ панела
  (`src/app/layout.tsx`).
- `sitemap.xml` и `robots.txt` се генерират автоматично (`src/app/sitemap.ts`,
  `src/app/robots.ts`); `/admin900` и `/api/*` са изключени от индексиране.
- Задайте `NEXT_PUBLIC_SITE_URL` на реалния домейн, за да са коректни всички абсолютни
  линкове в sitemap-а и Open Graph таговете.

## Полезни команди

```bash
npm run dev          # локален dev сървър
npm run build         # production build
npm run db:push       # приложи Prisma схемата към базата
npm run db:seed       # зареди демо съдържание в базата (CLI вариант на бутона в админ панела)
npm run db:studio     # визуален браузър за базата данни (Prisma Studio)
npm run hash-password -- "парола"   # генерира нов bcrypt хеш за админ паролата
```
